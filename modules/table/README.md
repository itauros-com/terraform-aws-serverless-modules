# table

A DynamoDB table with indexes, TTL, streams, protections and alarms. It wraps
[`terraform-aws-modules/dynamodb-table/aws`](https://github.com/terraform-aws-modules/terraform-aws-dynamodb-table)
`~> 5.0`.

## Usage

```hcl
module "tenants" {
  source = "…//modules/table"

  prefix = "acme-prod"
  name   = "tenants"

  attributes = { pk = "S", sk = "S", gsi1pk = "S" }
  hash_key   = "pk"
  range_key  = "sk"

  global_secondary_indexes = {
    gsi1 = { hash_key = "gsi1pk", range_key = "sk" }
  }

  ttl = { enabled = true, attribute_name = "expires_at" }
}
```

`range_key`, GSIs, LSIs, TTL, streams, PITR and deletion protection could not be exposed in the wiring
this library grew out of: single-table design was simply impossible, and the production tables had no
protection at all.

## The attributes

`attributes` is declared as a `name = type` map, not as a list of objects:

```hcl
attributes = { pk = "S", sk = "S", gsi1pk = "S" }
```

**Only** the attributes that take part in a key or in an index are declared. DynamoDB is schemaless for
everything else, and getting it wrong in either direction makes the table's creation fail with an error
that does not say which attribute:

- an attribute used by a key but not declared,
- an attribute declared but used by no key.

The module checks both and **names the attribute** in the message.

## Opinionated defaults

| | module default | AWS default | why |
|---|---|---|---|
| `billing_mode` | `PAY_PER_REQUEST` | `PROVISIONED` | no estimates required, no throttling on a spike, and on serverless's irregular workloads it costs less |
| point-in-time recovery | **enabled** | disabled | it is the only defence against a wrong application-level deletion |
| deletion protection | **enabled** | disabled | the table holds state, and must be protected from an absent-minded destroy |
| GSI `projection_type` | `ALL` | — | `KEYS_ONLY` forces a second read for every result, and you only notice the problem by measuring RCUs |
| `stream.view_type` | `NEW_AND_OLD_IMAGES` | — | it is the only type that allows computing a delta, and changing it later makes the consumers lose their position |

PITR costs in proportion to the table's size: on caching or rebuildable tables it is disabled explicitly.
Deletion protection must be set to `false` on throwaway tables — this repo's examples do that, otherwise
their `destroy` would not work.

## Alarms

Read throttling, write throttling, system errors. Threshold of **one** event on all three.

In on-demand mode throttling does not depend on the configured capacity but on partition limits: it
happens when the keys are badly distributed. It is the signal that the data model needs revisiting, not
that more capacity is needed — which is why it is worth seeing even without `PROVISIONED`.

## Notes

- LSIs can only be created **when the table is created**: adding one later requires recreating it, and
  with deletion protection enabled the plan stops before trying.
- With a CMK in `encryption.kms_key_arn`, pass `registry_entry` to the consumers' registry: the KMS
  permissions are generated by the grants.
- The TTL attribute must contain a Unix timestamp in **seconds**. A value in milliseconds raises no
  error: the items simply never expire.
