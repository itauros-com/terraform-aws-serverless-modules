| <a name="input_behaviors"></a> [behaviors](#input\_behaviors) | Behaviors by path, **in order**: CloudFront evaluates them in the order given and stops<br/>at the first `path_pattern` that matches. It is a list and not a map for that reason —<br/>Terraform orders a map by key, and here the order carries meaning.<br/><br/>    behaviors = [<br/>      { path\_pattern = "/api/*",     origin = "api",     preset = "api" },<br/>      { path\_pattern = "/exports/*", origin = "exports", preset = "private-files",<br/>        trusted\_key\_groups = ["downloads"] },<br/>    ]<br/><br/>`preset` resolves the cache policy, the origin request policy, the allowed methods and<br/>compression together:<br/><br/>\| preset \| cache \| origin request \| methods \|<br/>\|---\|---\|---\|---\|<br/>\| `static` \| CachingOptimized \| — \| GET, HEAD, OPTIONS \|<br/>\| `api` \| CachingDisabled \| AllViewerExceptHostHeader \| all \|<br/>\| `private-files` \| CachingOptimized \| — \| GET, HEAD \|<br/><br/>It exists because of one failure in particular: an API served with the static preset<br/>loses the `Authorization` header — the cache policy does not forward it — and answers<br/>401 on everything, with nothing anywhere saying why. ## Outputs

| Name | Description |
| ---- | ----------- |
| <a name="output_behaviors"></a> [behaviors](#output\_behaviors) | The resolved behaviors, in evaluation order, with what each preset expanded to. It is<br/>the output to read in a review: it says which path reaches which origin, whether it is<br/>cached and whether it is signed, without working it back out of the configuration. |
| <a name="output_bucket_policy_json"></a> [bucket\_policy\_json](#output\_bucket\_policy\_json) | The read statement for each bucket origin, by origin key, ready for<br/>`modules/bucket.policy_json` with `attach_policy = true`.<br/><br/>It has to go through the bucket module: S3 keeps **one policy document per bucket** and<br/>every write replaces it whole, so a separate `aws_s3_bucket_policy` here would silently<br/>drop the statements the bucket module always attaches — the deny on insecure transport<br/>among them — with neither Terraform nor AWS reporting the conflict. |
| <a name="output_bucket_policy_statements"></a> [bucket\_policy\_statements](#output\_bucket\_policy\_statements) | The same statements as `bucket_policy_json`, as objects rather than a document.<br/><br/>It is what a composition needs: a bucket fronted by two distributions has two statements<br/>in the one policy S3 allows it, and merging them structurally is the only way — a<br/>document embeds the distribution's ARN, which is unknown at plan, so `jsondecode` on it<br/>yields an unknown value nobody can index into. |
| <a name="output_distribution_arn"></a> [distribution\_arn](#output\_distribution\_arn) | The distribution's ARN. It is what scopes the buckets' OAC statement. |
| <a name="output_distribution_id"></a> [distribution\_id](#output\_distribution\_id) | The distribution's ID, the one to pass to a cache invalidation. |
| <a name="output_domain_name"></a> [domain\_name](#output\_domain\_name) | The `cloudfront.net` domain name, the target of the DNS records. |
| <a name="output_hosted_zone_id"></a> [hosted\_zone\_id](#output\_hosted\_zone\_id) | The zone ID to use in a Route53 alias record towards the distribution. |
| <a name="output_key_group_ids"></a> [key\_group\_ids](#output\_key\_group\_ids) | The key groups' IDs, by key. They are not the value used to sign: a signed URL carries<br/>the **public key's** ID in `Key-Pair-Id`, which is in `public_key_ids`. |
| <a name="output_origin_access_control_ids"></a> [origin\_access\_control\_ids](#output\_origin\_access\_control\_ids) | The OAC of every bucket origin, by origin key. |
| <a name="output_public_key_ids"></a> [public\_key\_ids](#output\_public\_key\_ids) | The public keys' IDs, keyed `<key group>/<key>`. It is the value that goes in the signed<br/>URL's `Key-Pair-Id`, so whoever signs reads it from here instead of copying it from the<br/>console. |
