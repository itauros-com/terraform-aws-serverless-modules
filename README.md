# terraform-aws-serverless-modules

A library of Terraform modules for serverless applications on AWS: Lambda, HTTP API Gateway, SQS, SNS,
DynamoDB, S3, Secrets Manager, EventBridge Scheduler, CloudFront.

The modules contain **no `provider` and no `backend`**: they are callable from any root config, which
remains the only place where credentials, region and state live.

## Usage

```hcl
module "app" {
  source = "git::https://github.com/itauros-com/terraform-aws-serverless-modules.git//modules/app?ref=v0.1.0"

  prefix    = "acme-prod"
  functions = { … }
  http_apis = { … }
  queues    = { … }
  topics    = { … }
  tables    = { … }
  buckets   = { … }
  secrets   = { … }
}
```

Every primitive is usable on its own, without going through `modules/app`:

```hcl
module "worker" {
  source = "git::https://github.com/itauros-com/terraform-aws-serverless-modules.git//modules/function?ref=v0.1.0"

  name      = "acme-prod-worker"
  image_uri = "123456789012.dkr.ecr.eu-west-1.amazonaws.com/worker:v1.2.3"

  resources = { queues = { jobs = { arn = module.jobs.arn, name = module.jobs.name, url = module.jobs.url } } }
  grants    = { "queue/jobs" = ["consume"] }
  env_from  = { JOBS_QUEUE_URL = { queue = "jobs" } }
}
```

## Principles

### 1. No magic in names

An application's environment variables are just names. A reference to another resource is declared
explicitly and typed through `env_from`, never inferred from the variable's name:

```hcl
env = {                                       # literal values
  LOG_LEVEL = "info"
}
env_from = {                                  # references resolved by the module
  DOCS_BUCKET = { bucket = "documents" }
  JOBS_QUEUE  = { queue  = "emails" }
  MONGO_URI   = { secret = "mongodb" }
}
```

No `try()` in the resolver: a key that does not exist makes the **`plan` fail**, it does not reach the
Lambda as a literal string to be discovered at runtime.

### 2. IAM derived from capabilities

Permissions are declared by intent, not as a list of actions. The policies are generated by
[`modules/grants`](modules/grants), which is pure computation and needs no provider:

```hcl
grants = {
  "bucket/documents" = ["read", "write"]
  "table/tenants"    = ["read", "scan"]
  "topic/operations" = ["publish"]
  "queue/emails"     = ["consume"]
  "secret/mongodb"   = ["read"]
}
```

Keys take the form `<type>/<name>` because the same name can belong to different services — a topic
`operations` and a queue `operations` coexist perfectly well. `extra_policy_statements` covers services
outside the table (SES, Bedrock, …).

An event source mapping on a queue **requires** the `consume` capability on that queue: without it the
plan stops, rather than creating a consumer with no permissions — one that would exist, receive nothing
and raise no error. The converse is legitimate — `consume` without a mapping is what you want when you
poll yourself — so coherence is *verified*, not enforced by creating resources as the side effect of a
permission.

### 3. Observability included, not optional

X-Ray tracing, a log group with explicit retention, alarms on errors, throttles and duration, and an
`on-failure` destination for asynchronous invocations are enabled by default and disabled explicitly.
A Lambda silently dropping events is not an acceptable default.

### 4. Wrapping, not rewriting

The primitives wrap the `terraform-aws-modules` modules where those are solid, adding the typed
contract, capability-derived IAM and the alarms. The resources written natively are the ones where
upstream is not enough. There are two: the queue policy with fan-in from several topics, where SQS
allows a single `Policy` attribute per queue and what is needed is one statement per topic rather than
one policy per subscription; and the CloudFront distribution in `modules/site`, where the upstream
module addresses the Origin Access Control by key — and that very indirection is the defect the module
exists to correct.

## Modules

| Module | Status | Description |
|---|---|---|
| [`grants`](modules/grants) | ✅ | Capability → IAM action table. Pure, no provider. |
| [`function`](modules/function) | ✅ | Lambda + role + log group + event source + alarms. |
| [`queue`](modules/queue) | ✅ | SQS + DLQ + redrive + fan-in policy + alarms. |
| [`topic`](modules/topic) | ✅ | SNS + subscriptions + policy. |
| [`table`](modules/table) | ✅ | DynamoDB with GSI/LSI, TTL, PITR, streams, deletion protection. |
| [`bucket`](modules/bucket) | ✅ | Private S3 + notifications + lifecycle + versioning. |
| [`secret`](modules/secret) | ✅ | Secrets Manager, create-only, no value in state. |
| [`security-group`](modules/security-group) | ✅ | Security group + VPC lookup by `Name` tag. |
| [`http-api`](modules/http-api) | ✅ | HTTP API Gateway + stage + authorizer + routes + domain. |
| [`site`](modules/site) | ✅ | Private S3 + CloudFront + OAC + Route53 + WAF hook. |
| [`registry`](modules/registry) | ✅ | ECR with immutable tags and lifecycle. |
| [`schedule`](modules/schedule) | ✅ | EventBridge Scheduler with DLQ. |
| [`observability`](modules/observability) | ✅ | Alarm topic, dashboard, log subscription. |
| [`app`](modules/app) | ✅ | Composition: registry, IAM, wiring graph. |

## Development

```bash
make help          # list the targets
make check         # fmt-check + validate + test — everything without AWS credentials
make test          # terraform test only
make docs          # regenerate the module READMEs (requires terraform-docs)
```

`make check` is what runs in CI on every PR, together with `tflint`, `trivy config` and the check that
the generated READMEs are up to date. Running `plan` against the `examples/` requires a test account and
is enabled by setting the `CI_AWS_ROLE_ARN` repository variable.

### Compatibility

- Terraform `>= 1.11` (callers use `use_lockfile` on the S3 backend; the modules use `optional()` with
  defaults and cross-variable validation).
- AWS provider `~> 6.0`.

A **breaking change** is any change to the variable contract or to the generated state addresses: the
first breaks callers' `plan`, the second requires `moved` blocks on their side. See
[CHANGELOG.md](CHANGELOG.md).
